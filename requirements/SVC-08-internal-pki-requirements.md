# SVC-08 — Internal PKI / Certificate Authority — Requirements

## 1. Overview

SVC-08 is the platform's private certificate authority: it issues the TLS certificates internal services present on
VLAN 20 (OpenBao's listener, Traefik's default `websecure` certificate for internal hostnames, backend hops behind
Traefik), publishes the root certificate every client trusts, and later issues client and device certificates
(MQTT mTLS for drones, Mender device identity). Today every internal TLS hop runs on a self-signed mock and its
clients skip verification; SVC-08 makes verification real. Embedded/drone projects depend on it for device identity,
every project depends on it indirectly through the shared services.

## 2. Scope

**In scope:**
- One private root CA and one issuing intermediate CA for the platform.
- Server certificates for shared VLAN-20 services and for Traefik's internal hostnames, issued by the installer of
  each consuming service ("push issuance"), with automated renewal before expiry.
- Distribution of the root certificate to the control node, the Traefik guest and every platform guest's trust store.
- Revocation (CRL; OCSP where the technology provides it) and a published CRL endpoint on VLAN 20.
- Flipping the existing self-signed mocks (Mock 1, 3, 5, B) to the real path where a CA is configured.

**Out of scope (this document's first implementation):**
- ACME for endpoints not behind Traefik (they use installer-issued certificates in this increment).
- Device enrolment protocols (EST, CMP, SCEP) for SVC-21/SVC-28; their certificate profiles are designed with those
  services.
- Publicly trusted certificates (Let's Encrypt through Traefik's existing resolver stays as is).
- HSM-backed keys.

## 3. Technology selection

Decided in [ADR-0028](../.kiro/decisions/0028-svc08-internal-ca-technology-and-issuance-mode.md) (Accepted
2026-11-15): **the OpenBao PKI secrets engine on the existing SVC-07** (OpenBao, Linux Foundation, already a flagged
non-EU exception). No new guest; issue API, CRL/OCSP and ACME built in. **EJBCA is removed**: its Community Edition
has no ACME and is vendor-positioned for non-production. **step-ca** (Smallstep, US, flagged) stays the documented
lightweight alternative. **SVC-10 internal DNS is built first**, so ACME serves everything behind Traefik from the
start; endpoints not behind Traefik get installer-issued certificates. The sections below that list Option A/C
details are kept for the alternative only.

## 4. Multi-tenancy model

**Shared platform service** (catalog tenancy "Shared"). One root and one issuing CA serve the platform. Isolation is
by **issuance policy**: each consuming service may request certificates only for its own names (a role or
provisioner per certificate class, allowed-domain lists per service). Projects never receive the CA's administrative
credential. Per-project device CAs (if SVC-21/28 need them) are a later design.

## 5. Functional requirements

- **FR-1**: The CA MUST hold one root (validity 10 years, used only to sign the intermediate) and one issuing
  intermediate (validity 3 years). The root private key MUST NOT be exportable from the CA after creation.
- **FR-2**: A consuming service's installer MUST be able to obtain a server certificate (key generated by the CA or
  by the service, SANs = its DNS names and VLAN-20 IP) with one idempotent, non-interactive call, authenticated with a
  credential scoped to that service's allowed names.
- **FR-3**: Leaf certificates MUST default to a 90-day validity and MUST be renewed automatically when less than 30
  days remain, by re-running the consuming installer or a scheduled job; renewal MUST be a no-op when not due.
- **FR-4**: The root certificate MUST be published (VLAN-20 HTTP endpoint and the repository's generated artifacts
  directory, never with a private key) and installed in the trust store of the control node and of every platform
  guest by the `common` role or an equivalent shared step.
- **FR-5**: Revocation MUST be possible by serial number, and a CRL MUST be published on VLAN 20 and refreshed at
  least every 24 hours.
- **FR-6**: Each existing mock MUST flip to the real path when the CA is configured, without changing the consuming
  service's file paths: OpenBao listener (Mock 1), Traefik default certificate for internal names (Mock 3), the
  Grafana route (Mock B, `obs_tls_real_ca_available`), and backend hops verified through ADR-0018 `rootCAs`.
  The mocks stay as permanent default-off stand-ins.
- **FR-7**: Clients that today skip verification because of a mock (`-tls-skip-verify`, `validate_certs: false`,
  `tls_skip_verify` in agent configs, `consumer_openbao_tls_self_signed`) MUST verify against the root when the CA is
  configured (closes WS-C13).
- **FR-8**: Certificate issuance and revocation MUST be audited (who, which names, serial, expiry).

## 6. Non-functional requirements

- **Availability**: issuance is needed at install and renewal time only; a CA outage MUST NOT break running services
  (certificates stay valid). Target: recover the CA from backup within a day.
- **Sizing**: negligible for Option B (inside SVC-07); Option C 1 vCPU / 512 MB / 4 GB LXC; Option A 2 vCPU / 4 GB /
  20 GB LXC plus its database.
- **Backup/DR**: CA key material and the issued-certificate database MUST be in the backup scope of SVC-32 (or of the
  SVC-07 Raft snapshot for Option B). Losing the root key means re-issuing every certificate and redistributing the
  root.
- **Retention**: issued-certificate records kept for the root's lifetime.

## 7. Infrastructure architecture

- **Option B**: no new guest; mounts on the SVC-07 primary (`10.0.20.10`). No ledger row.
- **Option A/C**: one unprivileged LXC on VLAN 20 at the next free Host_Index_Authority index (15 is now planned for
  SVC-10),
  `svc_code: svc08`, `anchor: true` (stateful CA keys). The row is added to
  `infra/platform-foundation/host-indices.yaml` when the option is chosen; index 3 stays a documented gap.
- Storage `local-zfs` (or `local-lvm`) with `prevent_destroy`.

## 8. Terraform scope

- Option B: none (configuration of an existing service).
- Option A/C: one root `infra/projects/svc-08-internal-pki/` (state `svc-08-internal-pki`) using `proxmox-compute`;
  outputs `inventory_hosts`, `ca_url`.

## 9. Ansible scope

- A CA role (`pki_ca`) that creates the root and intermediate once, the issuance roles/provisioners per service class,
  the CRL endpoint, and writes the public root certificate to a known path.
- A shared issuance role (`pki_issue`) that a consuming installer includes: inputs = names, IPs, destination paths,
  owner/mode, reload handler; idempotent (skip when the current cert is valid for more than 30 days and matches the
  requested names).
- A shared trust role step (in `common` or a `pki_trust` role) that installs the root into the OS trust store.
- Orchestrator `ansible/playbooks/svc-08-bootstrap.yml` with the four phases and a clean-slate, per
  `service-installer.md`.

## 10. CI/CD pipeline

Offline gate as for every service (lint, `terraform validate` for Option A/C, pytest). Live acceptance on the
throwaway cluster. State name `svc-08-internal-pki` (Option A/C).

## 11. Secrets & credentials

- CA private keys: generated inside the CA, never exported (Option B: inside OpenBao; Option A/C: on the CA guest's
  data volume, encrypted at rest by the host-layer controls).
- Per-service issuance credentials: OpenBao AppRole or token scoped to one PKI role (Option B), or a step-ca
  provisioner / EJBCA end-entity credential stored in OpenBao (A/C).
- Leaf private keys: generated on or for the consuming guest, written 0600, never logged.
- Rotation: leaves every 90 days (FR-3); the intermediate before 2 years; the root by a documented ceremony.

## 12. Security & hardening baseline

- Least privilege per issuance role (allowed domains, no wildcard except Traefik's internal default, max TTL).
- CA administrative access only from the control node; never handed to projects.
- The root certificate is public; private keys never appear in the repository, logs or banners.
- TLS on the CA's own API (Option A/C); Option B inherits OpenBao's listener.

## 13. Observability hooks

- Certificate expiry metric for every issued leaf (exporter or textfile collector on each guest) and the
  SVC-17/18 alert "certificate expiry < 14 days".
- CA availability (API health) scraped by Prometheus; CRL age alert (> 36 hours).
- Issuance and revocation events in the audit log shipped to Loki.

## 14. Acceptance criteria

- [ ] From-scratch live bring-up on the throwaway cluster under `AGENT_LIVE_AUTHORIZED` + the throwaway guard: root
      and intermediate exist; the root is in the control node's and every guest's trust store.
- [ ] OpenBao's listener serves a CA-issued certificate and `bao status` succeeds **without** `-tls-skip-verify`.
- [ ] Traefik serves a CA-issued certificate for internal hostnames; `curl --cacert root.pem https://grafana.<domain>`
      succeeds without `-k`.
- [ ] A revoked test certificate appears in the published CRL.
- [ ] A re-run issues nothing new while certificates have more than 30 days left; a forced short TTL renews.
- [ ] Clean-slate leaves `terraform state list` empty (Option A/C) or removes the PKI mounts and trust entries
      (Option B), with consumers falling back to their mocks only when explicitly selected.
- [ ] Distinct host IP for the CA guest against the ledger (Option A/C).

## 15. Open questions / assumptions

- **Technology and issuance mode**: ADR-0028 (operator decision required before implementation).
- Internal DNS (SVC-10) absence: ACME is deferred; push issuance is assumed.
- Whether the root key should be generated offline (a ceremony on an air-gapped machine) instead of inside the CA.
  Recommended: inside the CA for this homelab posture, revisit for production.
- Device PKI for SVC-21/28 is assumed to reuse this CA's root with a separate intermediate, designed later.
